# 开源范围规范

> 本文件定义本仓库**包含什么**、**不包含什么**，以及执行顺序。
> 它是规范，不是执行记录。

## 一、要开源的功能

| 子功能 | 说明 | 剥离难度 |
|---|---|---|
| 天梯榜主视图 | 全部 CPU 排行，服务端渲染 | 中（上游为单体文件） |
| 架构筛选 | 全部 / x86_64 / ARM64 / ARMv7 / Other | 低 |
| CPU 详情页 | 规格 + 多维度跑分 | 中 |
| CPU 对比页 | 两两对比 | 低 |
| 图表 | ECharts，本地打包 | 低 |

架构枚举值：`x86_64` / `ARM64` / `ARMv7` / `Other`

## 二、技术栈

| 层 | 技术 |
|---|---|
| 后端 | PHP 8.1，无框架，原生 PHP |
| 数据库 | MariaDB 10.6 |
| 前端 | 原生 JS + ECharts（本地打包，非 CDN） |
| 渲染 | PHP 服务端渲染为主 |

## 三、绝对不包含（红线）

- **用户提交记录的隐私字段**：任何可关联到具体提交者的信息 —— 邮箱、IP、站内用户 ID、姓名、截图及其哈希、审核人、审核备注
- **用户体系**：注册 / 登录 / 会话 / 验证码
- **商业逻辑**：会员定价、支付、订单、返利、带货
- **后台管理端**
- **网络情报相关模块**
- **任何真实密钥或凭据**
- **基础设施**：Web 服务器配置、部署脚本、备份脚本

## 四、配置约定

沿用上游已有的安全模式：

```php
<?php
// config/xxx.example.php
// 复制为 config/xxx.php 后填入自己的值；
// 也可以把真实值放在 Web 根之外的文件里，用 getenv() 读取。
return [
    'api_key' => getenv('XXX_API_KEY') ?: '',
];
```

**要点**
- 仓库里只允许出现 `*.example.php`
- 真实值通过环境变量或 Web 根之外的文件注入
- `.gitignore` 已排除 `config/*.php`，但保留 `*.example.php`

## 五、数据策略

**只开源代码 + 少量示例数据**，不附带任何生产数据快照。

- `sql/`：脱敏后的建表语句，去掉全部隐私字段
- `data/`：10–20 条示例记录，够看清效果即可

理由：全量数据是上游站点的核心资产，公开后容易被直接搬运，反而稀释自身流量。

## 六、执行顺序

```
阶段 1  文件分类 → 产出「可开源 / 需改造 / 禁止开源」三份清单，等用户确认
阶段 2  代码剥离 → 先做天梯榜主视图与架构筛选，再做详情页 / 对比页
阶段 3  脱敏与模板化 → 建表 SQL 去隐私字段；配置改 example 模式
阶段 4  本地验证【不能省】→ 用 Docker 起干净环境，确认 clone 下来能跑通
阶段 5  发布 → README 截图、Demo 链接、提交到相关 awesome 清单
```

## 七、执行者须知

- **不要**把上游文件整份复制过来，必须逐文件审查
- 不确定是否敏感的内容，**列出来问，不要自行决定**
- 提交前用密钥扫描工具（`gitleaks` / `git-secrets`）过一遍
- 本仓库当前是**骨架**：`public/`、`includes/`、`sql/`、`data/` 均为空
